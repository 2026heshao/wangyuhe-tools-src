# LaunchDeck 统一动效令牌（Animation Tokens）设计方案

> 状态：设计稿（未落地）
> 目标：把散落在各 UI 文件里的"魔法时长 + 各自 Easing"，收敛为**一套单一事实来源**，让整体动效手感统一、可控、可调，并锁定已踩过的卡顿约束。

---

## 0. 为什么需要

当前动画数值全部以魔法数硬编码在 3 个文件里，各写各的，缺乏一致性：

| 位置 | 硬编码值 |
| --- | --- |
| `floating_ball.py` | hover 140ms / press 100·150ms / drag 150ms / settle 120ms / pulse 2800ms / snap 220ms |
| `slide_panel.py` | AppItem hover 120ms / enter 120ms(stagger 35ms 封顶 300) / launch 100·150ms / scroll 200ms / 面板滑入 180ms 滑出 150ms |
| `settings_dialog.py` | 入场 200ms / 退场 150ms / 位移动 8px |

问题：
- 节奏不统一（同是"消失"，面板 150ms、弹窗 150ms、AppItem hover 是缩回，各自手感不同）。
- Easing 选择零散，缺统一"原则"。
- 改一个速度维度时，无法整体收敛（虽有 `anim_speed` 全局倍率，但未强制 `_ms()` 走统一换算）。
- 你此前为防卡顿强推的"同一属性禁止双动画并发"（约束3）目前靠注释约定，不具约束力。

## 1. 令牌数据模型

新增 `ui/anim_tokens.py`，核心是一个不可变数据类 + 全局注册表。

```python
# ui/anim_tokens.py（示意）
from dataclasses import dataclass
from PyQt6.QtCore import QEasingCurve

@dataclass(frozen=True)
class Motion:
    key: str                   # 令牌名，如 "panel.enter"
    duration: int              # base 时长 @ 速度=1.0，单位 ms
    easing: QEasingCurve       # 固定从下方"色板"取，禁止新造
    stagger_ms: int = 0        # 顺次延迟（用于列表逐项入场），0=无
    travel: int = 0            # 位移幅度(px)，用于"动多动少"的口径统一
```

**关键原则**：令牌**按"意图"分组**，不按控件分组。同一种意图在不同控件上的手感应当一致，差异只保留在 `duration`/`travel` 数值层面。

## 2. 意图色板（Palette by Intent）

把整程序动效归类为 **6 类意图**，每类固定节奏区间：

| 意图 | 用途 | 节奏 | 主 Easing | 现行对应 |
| --- | --- | --- | --- | --- |
| `MICRO` | 按下、微反馈、瞬时高亮 | 90–150ms | OutCubic | 悬浮球 press 100ms、AppItem hover 120ms |
| `ENTER` | 一切"出现"：面板滑入、弹窗入场、图标入场 | 160–220ms · 快起步缓到位 | **OutCubic** | 面板 180ms、弹窗 200ms |
| `EXIT` | 一切"消失"：面板滑出、弹窗退场 | 140–180ms · 匀缓 | **InCubic** | 面板 150ms、弹窗 150ms |
| `MOVE` | 位移动/滚动/吸附 | 200–260ms | OutCubic | snap 220ms、scroll 200ms |
| `SPRING` | 弹性回弹反馈（点击发射/释放回弹） | 100–180ms 回程 | **OutBack** | launch 回弹 150ms、press 释放 150ms |
| `DECOR` | 循环装饰（闲置呼吸） | 长周期 | InOutSine | pulse 2800ms |

## 3. 核心设计原则（写入方案，落地时作为强规则）

### 3.1 不对称进出（Asymmetric Motion）——"丝滑灵动"的灵魂
- **进场快、起步急、缓到位** → `OutCubic`（一开始动得快，视觉上"主动迎来"）
- **退场匀、不抢眼** → `InCubic`（避免"停住/生硬消失"的顿挫感）
- 现状已零星符合（面板 180 Out / 150 In），但 `press 释放`、`launch 回弹` 用了 `OutBack` 属于"反馈"类，不算违反——它们走 `SPRING`。

### 3.2 Easing 色板收敛
只开放以下 6 种 Qt Easing，任何新动画必须从色板取，**不得新造**：

- `OutCubic` — 主进场 / 位移 / 悬停（推荐主力）
- `InCubic` — 退场
- `InOutCubic` — 对称缩放收尾（悬浮球 hover 缩小）
- `OutBack` — 弹性回弹（仅反馈，**慎用**，采样过冲值别太大）
- `InOutSine` — 循环装饰（呼吸）
- `Linear` — **列入禁用**（会产生"停住感"）

### 3.3 全局唯一速度档
保留现有 `anim_speed`（0.5–2.0）。**令牌里只存 base 时长**，取用时统一：

```python
def dur(speed: float, base: int) -> int:
    return max(1, int(base / max(0.5, min(2.0, speed))))
```

任何界面代码不得再 `int(... / self._anim_speed)` 自行换算，统一走 `anim_tokens.dur()`。

### 3.4 强约束：同一属性单动画并发（锁）
把 `floating_ball.py` 里为防卡顿手写的"约束3"提升为令牌层的统一入口：

```python

    # 从机制上杜绝两套动画并发操作同一属性（历史：呼吸 vs hover 卡顿根源）
```

所有"会操作同一 Qt 属性的动画"必须走 `play()`；只对一次性动画保留 `DeleteWhenStopped`。

## 4. 模块组织

```
ui/
  anim_tokens.py            # 唯一事实来源（新增）
    - Motion (dataclass)
    - TOKENS                # dict[intent][sub] -> Motion 注册表
    - dur(speed, base)      # 时长换算
    - play(target, prop, key, ...)  # 统一入口 + 单属性锁
    - STAGGER_LIST(max)     # 逐项入场延迟序列，统一封顶
```

各 UI 文件只 `import` 令牌，界面层不再出现裸 `duration`/`easing` 魔法数（位移像素 `travel` 也收进令牌）。

## 5. 迁移映射表（现状 → 令牌）

落地时按本表逐一替换：

| 现有魔法 | 归类 | 提议令牌 | 备注 |
| --- | --- | --- | --- |

| 悬浮球 press 100ms(Out) / 150ms(OutBack) | MICRO / SPRING | `ball.press.down` / `ball.press.up` | 下/回弹 |

| 吸附 220ms OutCubic | MOVE | `ball.snap` | |
| AppItem hover 120ms OutCubic | SWELL | `item.hover` | |
| AppItem 入场 120ms OutCubic + line35ms | ENTER | `item.enter` (stagger 35, 封顶300) | |

## 7. 与"丝滑化建议"的关系

本方案是问题3所有丝滑化建议的**地基**：
- "进场/退场不对称" → 直接由 3.1 规则覆盖。
- "滚动惯性更真实" → 后续只需替换 `panel.scroll` 令牌的 `duration` 派生逻辑，不需要改结构。
- "反馈弹性统一" → 由 `SPRING` 意图集中的 `OutBack` 色板统一。

因你选择"先不改动"，本文档仅作方案沉淀，代码未改动。
